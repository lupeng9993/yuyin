# 意图协议 v3（多动作）

## 为什么改

原文档是单动作协议（`{"action": ...}`）。实测中一句口语经常包含两件事，
例如「打开音乐，音量调小一点」，单动作协议只能丢掉一半。v3 允许一句话最多 **5 个动作**，
按顺序执行，单个失败不阻断后续。

## 结构

```json
{
  "actions": [
    { "action": "navigate", "destination": "大明湖景区" },
    { "action": "send_wechat", "contact": "张三", "message": "我四十分钟到" },
    { "action": "other", "raw_text": "打开网易云，音量调小一点" }
  ]
}
```

### 约束

| 规则 | 说明 |
|---|---|
| 动作数量 | 1–5 个，超过时只保留前 5 个 |
| 动作类型 | 只能是 `navigate` / `send_wechat` / `other` / `unknown` |
| `unknown` 混入 | 整体判定为 `unknown`，**一个动作都不执行** |
| 字段缺失 | 该动作降级为 `unknown`（例如导航没有目的地） |
| 兼容性 | 解析器同时接受旧格式 `{"action": "..."}`，视为单动作 |
| 清洗 | 自动去掉 ```` ```json ```` 围栏、前后解释文字，只取最外层 JSON |

## 各动作字段

| 动作 | 必填字段 | 执行器 |
|---|---|---|
| `navigate` | `destination` | 高德 Web API 地理编码 → 唤起高德 App |
| `send_wechat` | `contact`、`message` | 无障碍：搜索联系人 → 输入 → 发送 |
| `other` | `raw_text` | 系统执行器二次解析（音量 / 截屏 / 打开应用 / 媒体控制） |
| `unknown` | `reason` | 不执行，只播报原因 |

## 固定系统提示词

所有云端适配器使用**同一份**提示词，唯一来源：
`app/src/main/java/com/voiceassistant/nlu/SystemPrompt.kt`。

## 本地规则（第一优先级）

本地规则先于云端执行，命中即结束，不发起网络请求。规则在
`app/src/main/java/com/voiceassistant/nlu/RuleEngine.kt`：

- 整句优先匹配（避免把「给张三发微信说，我四十分钟到」里的逗号当分隔符）
- 整句不中才按 `，。；` 与「然后 / 接着 / 再」切子句，逐句匹配
- 最多 5 个子句

## 降级

云端失败（断网、超时、401、403、429、5xx、无法解析）时：

- 「自动降级」开 → 再跑一次本地规则，命中就执行
- 「自动降级」关 → 直接播报失败

## 二次确认

- `send_wechat`：技能一开启就**强制**确认，与来源无关；10 秒内没听到「确认」即视为取消。
- `navigate`：由设置开关控制，默认关闭。
- 多动作排队执行时，取消某一步只跳过那一步，后续动作继续。
